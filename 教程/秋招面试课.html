第一课　从一次工具调用推到策略梯度

白板目标　面试官给你一段聊天记录，你能把它变成训练样本，写出谁在采样、优化什么、哪一项可以求梯度。

第一遍读到「从期望到一行 PyTorch」就动笔。把下表的最后一个动作改成提交 B，重新计算回报，圈出三个动作各自的 logp。接着遮住 B 的报价，解释为什么同一条动作序列已经不足以让人复核这次判分。这个对比就是实现 rollout 时保存工具返回的理由。

先走一遍环境

用户要求“比较两家的商品价与运费，查全两家后，提交到手价最低的一家”。环境存着 A、B 两份报价，智能体只能看到查过的内容。每查一次或提交一次都算一个动作，最多三个动作。这里把一次工具调用压成一个离散动作，下一课再展开到语言模型的 token。

时刻 发出者 公开历史增加的内容 动作损失 环境反馈
初始 用户 请求比较到手价 无 隐藏两份报价
0 策略 查 A 有 A 返回商品价 9，运费 14
1 策略 查 B 有 B 返回商品价 13，运费 8
2 策略 提交 A 有 A 合计 23，B 合计 21，失败，奖励 0

从时刻 2 往前想。智能体已经具备选 B 的全部信息，却选了 A。你可以把这个失败归入“比较或提交错误”。如果动作变成“查 A、查 A、提交 B”，虽然碰巧选对，仍缺 B 的证据。这时故障在查询阶段。只保存末尾的 0 就无法区分两类错误。

如何定义“学会”

完整状态 st 包含报价、已查询集合和剩余预算。观测 ot 只含工具愿意返回的字段。历史 ht=(o0,a0,o1,…,ot) 是策略的输入。若同一个可见状态对应不同隐藏报价，单步观测无法唯一决定最佳动作，这是部分可观测决策问题。项目把已见报价与剩余步数压成小张量，语言模型通常把对话历史串进上下文。随便截掉旧的报价，会改变问题的可解性。

策略 πθ(a∣h) 给出下一动作的概率。回报 Gt=∑k=tT−1γk−trk。有限、短回合且最终只看任务完成时，可以取 γ=1。若按 token 定义步长且 γ=0.99，相隔 100 个 token 的终局奖励权重只有 0.99100≈0.366。这等于额外表达了偏好短距离反馈的目标，选步长时应说清楚。

对当前策略，Vπ(ht)=E[Gt∣ht]，Qπ(ht,at)=E[Gt∣ht,at]，Aπ=Qπ−Vπ。Bellman 关系把未来装进下一步的价值：

Qπ(ht,at)=E[rt+γVπ(ht+1)∣ht,at].

两家都已查到，策略以 0.7 概率提交赢家，以 0.3 概率提交输家。成功得 1，此时 V=0.7，两个动作的优势分别为 +0.3 和 −0.7。平均优势 0.7(0.3)+0.3(−0.7)=0。优势回答的是“比这个位置通常会做得好多少”。

从期望到一行 PyTorch

轨迹概率是初始状态概率、各步策略概率和环境转移概率的乘积。设环境与奖励不显含 θ，轨迹回报为 R(τ)。用 ∇p=p∇logp 可得：

∇θJ=∇θ∑τpθ(τ)R(τ)=Eτ[R(τ)∑t∇θlogπθ(at∣ht)].

环境转移项在对数中相加，对 θ 的导数为零。时间 t 以前的奖励在给定历史后已经确定，乘以当前动作的 score 后期望为零，因此可换成 reward-to-go。若 J 显式折扣且从初始时刻取期望，前面还有 γt 的权重；本课手算都取 γ=1。

在固定历史下，∑aπ(a∣h)∇logπ(a∣h)=∇∑aπ(a∣h)=0。因此减去只依赖历史的 baseline 不改变该项期望。实作时令 loss = -(logp * advantage.detach()).sum(-1).mean()，先对同一轨迹的动作求和，再对轨迹平均。变长序列要先屏蔽无效位置。反传沿选中动作的 log 概率流动，离散采样和外部工具无需可微。

用一个标量验方向。 最后一步用 logit z 选 B，p=σ(z)，B 是赢家。期望成功率就是 p，其导数 p(1−p)>0。采到 B 时，∂logp/∂z=1−p，发生概率 p。采到 A 时回报为 0。两项相加恰为 p(1−p)。把 loss 前的负号删掉，用梯度下降一步就会朝相反方向走。

一次面试会怎样追问

“0 分的动作就永远学不到吗？” 不减 baseline 的二元回报中，单条失败轨迹的这一项确实为零。如果 baseline 估计同一状态通常得 0.7 分，失败样本优势就是 −0.7。若当前任务整组样本全失败，组内居中又会让所有优势归零。区分三种估计器，才能决定要改 baseline 还是改探索。

“复制终奖给每一步，能识别是哪一步做错了吗？” 这给出了合法的整轨迹梯度估计。单条样本里，必要的查询与错误的提交共享信号，方差可能很高。收集许多类似前缀、尝试不同后续动作可以分辨贡献。如果环境可精确克隆，可固定两次工具结果，只替换最后的选择评估反事实。加入步骤奖励前先验证它是否改变了最优策略。

“什么时候上下文 bandit 就够了？” 若给定问题后只需一次选择，后续无可利用的新观测，可把一次决策视作 bandit。把全段回答当一个超大动作，有时也能优化终奖；如果中途工具会返回新报价，就必须对这条反馈之后的决策建模。否则无法表达“看完 A 再决定下一步”。

第二课　拿到什么数据，就能做什么更新

假设初始模型会输出工具调用，但常在拿到第一份报价就提交。面试官给了你三类数据：专家演示、同题一好一坏的偏好对，以及每次尝试都能重置的环境。先弄清它们提供什么反馈，再选算法。

第一遍的作业。 用同一个输入解释四种选择：演示中预测哪个动作，偏好对中谁胜过谁，critic 怎么给当前前缀估值，同题多次采样怎样形成组内优势。在本项目中实际训练的是 SFT 和一个带组相对优势的裁剪策略；GAE 有单独的张量练习，DPO 用偏好对手算。把「跑过」「写过」「能推导」标在各项旁边。项目训练循环 · 张量练习

SFT、拒绝采样与 DPO

SFT 对专家动作做条件最大似然，最小化 −∑t∈Mlogπθ(yt∣ht)。M 只含演示中模型应该输出的位置。十几条干净的演示足以教一个小模型按格式先查两家。若专家从未示范“工具失败后如何恢复”，部署时模型落入这个前缀，模仿损失就缺少直接监督。可收集失败前缀上的专家纠正再训练。

拒绝采样微调让当前模型每题生成若干轨迹，用验证器留下成功轨迹做 SFT。它可以把搜索得到的好行为蒸馏回单次生成。某个题型从来采不到正确解，它在过滤后的数据中就消失了。训练集还会过度代表容易被采对的题，要记录各题型被保留的比例。

DPO 使用固定偏好对 (x,yw,yl) 和冻结的参考策略。记 u(y)=logπθ(y∣x)−logπref(y∣x)，标准损失为 −logσ(β[u(yw)−u(yl)])。序列对数概率通常按有效响应 token 求和。给定偏好方向后可直接训练，不必每次调用环境。其推导联系了带 KL 正则的最优策略与 Bradley–Terry 偏好模型。若参考与当前策略起初相同，括号内差为零，loss 等于 log2，梯度仍会提高赢家相对输家的对数几率。DPO 论文

选择题。 手头只有两万对人工偏好，工具现在无法重放，可先用 DPO 检查偏好质量与留出表现。若有准确可执行的终局验证器、目标是学会在新观测后行动，则在线采样能发现演示没覆盖的轨迹。可先 SFT 确保调用语法有意义，再比较拒绝采样与在线 RL 的额外成本和收益。

PPO 的三种“策略”

符号 在做什么 混淆后的症状
πold 生成这批动作的行为策略，冻结当时的选中动作 logp 每一轮优化都重算分母，ratio 人为等于 1
πθ 正在更新的策略，给相同历史与动作重新打分 错用另一个前缀会产生伪造的概率变化
πref 正则化的参考策略，常取 RL 开始前的 SFT checkpoint 把“偏离上批”误当成“偏离初始能力”

对于采样的动作，ρt=exp(logπθ(at∣ht)−logπold(at∣ht))。PPO 最大化裁剪替代目标：

Lclip=Et[min(ρtA^t, clip(ρt,1−ϵ,1+ϵ)A^t)].

取 ϵ=0.2，只看单项。A^=2,ρ=1.5 得 min(3,2.4)=2.4，再抬高该动作概率也没有额外收益。A^=−2,ρ=1.5 得 min(−3,−2.4)=−3，增加坏动作概率仍受惩罚。若 A^=−2,ρ=0.6，则 min(−1.2,−1.6)=−1.6。因此“所有越界样本都停止更新”会算错负优势的方向。裁剪作用在样本目标，不能保证所有状态的 KL 均低于某个硬阈值。PPO 论文

在 actor–critic 版本里，critic 可以用回报目标 Vtarget 回归，actor 使用冻结的优势；实际还可有熵项、参考 KL 和 value loss。若将 −βlog(π/πref) 作为采样奖励，就需说明 logp 来自哪一版策略，何时冻结。若将解析 KL 加到 actor loss，说明方向与权重，检查有无重复计入。

GAE 到底平滑了什么

令 bt 表示下一状态允许 bootstrap，ct 表示同一段轨迹的优势还可以向后递推。写成两道门，一行便能处理采集截断和 episode 边界：

δt=rt+γbtV(ht+1)−V(ht),A^t=δt+γλctA^t+1.

真正 terminal 时两道门都关。若采集器只拿到一个仍可继续的片段末尾，且有该末尾真实后继状态的价值，可令 b=1,c=0。如果“三步预算耗尽”本身就是任务失败，按环境终止处理。自动 reset 环境时尤其要区分末状态和下一局初状态。GAE 论文

手算一次。 两步任务 r=[0,1]，V=[0.4,0.5]，第二步真正结束。取 γ=1,λ=0.5，δ=[0.1,0.5]，从后往前算 A^=[0.35,0.5]。当 λ=0 时只用一步 TD，受价值误差影响较大。当 λ=1 且完整终止时，首步成为实际回报减 V0=0.6。在估值有误、轨迹长、奖励有噪声的情形，选择 λ 会改变偏差与方差的折中。

GRPO 为什么能去掉 critic

一次分组需要花多少采样？ 若同一道题的单次成功率为 p，成功/失败独立，二元奖励组有非零方差的概率是 1−pG−(1−p)G。p=0.01,G=8 时仅约 7.7%。简单扩大 G 会消耗更多工具调用。还可以增加易题、改善初始策略或在固定预算下比较“多题少样本”和“少题多样本”。若工具服务共享一次缓存错误，独立性会失效。

处在不同位置的 KL

在已访问的同一历史 h，前向 KL 为 ∑apθ(a∣h)[logpθ(a∣h)−logpref(a∣h)]。项目只有四个动作，可以直接求和。若 a~pθ，单个 logpθ(a)−logpref(a) 允许为负，其期望才是非负 KL。若样本来自旧策略，直接抽样平均测量的是旧分布下的量；解释为当前策略 KL 需要相应条件或权重。大词表实现会选采样估计或分块计算，请先问日志定义。

面试官的三个变体

先检查一个前置概念。自注意力的权重来自 softmax(QK⊤/dk+M)，因果 mask 让当前位置看不到未来，padding mask 让它忽略填充；乘上 V 才得到上下文表示。前面的助手动作 mask 则决定哪些预测进入标量损失。这三个 mask 回答不同问题。增量生成复用旧 token 的 K、V，省去重复计算历史表示；训练侧一次处理整段序列仍需正确的因果约束。

一、变长轨迹如何加权？ 轨迹一有 1 个动作，单项损失为 1；轨迹二有 3 个动作，单项损失均为 3。所有动作取平均得 (1+9)/4=2.5。每条轨迹先平均再按轨迹平均得 (1+3)/2=2。每条求和再按轨迹平均得 (1+9)/2=5。最后一种对应朴素的整轨迹 log 概率求和。实际训练中的长度归一化、全局 token 归一化和终止奖励都能影响长度偏好。项目采用第三种，张量练习采用第一种，换实验要记录分母。分布式训练各 rank 的有效动作数可能不同，先求局部均值再平均会给短 batch 过高权重。

二、packing 怎样静悄悄地泄漏？ 直接把两个不同任务首尾相接，即便第一个位置的 loss 被遮住，第二条轨迹仍可能通过注意力读到上一条。按样本边界做分块因果注意力，并检查位置 ID、目标偏移、组 ID、GAE 递推均没有跨段。给第一条序列换成随机 token，第二条在相同位置设定下的 logits 应在容差内保持一致。

三、相同 checkpoint 为什么 ratio 不是 1？ 优先检查模型版本、输入 token 与位置、dropout、温度和 top-p。设模型原分布 (0.8,0.2)，温度 T=2 后分布约为 (2/3,1/3)。若抽到第二项，用原分布当前概率除采样概率就得到约 0.6，同一参数也会偏离 1。必须定义实际优化与记录的是哪种分布。top-p 会截断支持集，记录截断后的 logp 可以解释行为样本，无法凭此恢复从未被采到的动作。在多轮工具学习中，对齐采样和优化的分布是最容易验证的起点。

探索和长程归因的两类失败

没有成功样本。 检查同一初始任务的多条轨迹是否覆盖不同工具和参数。若连规则专家都失败，先修环境。若规则能过、模型连工具 schema 都写不对，可用少量 SFT 冷启动或短任务课程。比较相同环境调用预算下的首次成功时间、出现成功的任务比例、无效调用率。增大温度也可能只增加无效 JSON。

成功存在，但对中间决策没有分辨力。 固定工具前缀，分别采多个后续动作，估算由该前缀出发的成功概率；在环境可克隆时分支重放。过程奖励能让反馈更密，但“每调用一次给 0.1”会奖励重复查询。势函数塑形 r′=r+γΦ(s′)−Φ(s) 的折扣和在固定初态、终止势为零等条件下只差常数，可保持最优策略。真实项目的启发式步骤分很少天然满足这些条件，应独立验证最终成功率。

预算也属于目标。 比较“总成功率”和“每千次工具调用完成多少任务”；另报 P95 延迟以及超时率。只惩罚调用数可能让模型学会盲猜。业务有硬约束时，可报告约束内的成功率，或给同一预算下的成功率曲线，再决定训练时的成本权重。

区分 pass@k、单次成功与稳定性

给定一道题，从同一策略独立采样。如果单次成功率为 p，至少一次成功的概率是 1−(1−p)k；连续 k 次全成功的概率为 pk。当 p=0.6,k=4，前者为 0.9744，后者仅 0.1296。后者对应工具 agent 常讨论的 pass^k 稳定性。若每道题难度不同，应先按题算，再对题平均。对全题平均 p 做幂运算一般不成立。τ-bench 论文

实测某题独立生成 n 个样本，其中 c 个成功，n≥k。从这些样本抽 k 个，pass@k 估计为 1−(n−ck)/(nk)，全成功估计为 (ck)/(nk)，上数小于下数时组合数按零计。n=5,c=2,k=2，至少一次为 1−3/10=0.7，全对为 1/10=0.1。给用户返回一次答案还需要能选出成功样本的选择器；离线 oracle 能看到验证器答案时，报告 best-of-k 须同时说明选择器、尝试次数与成本。

用配对任务判断差异

两个策略跑同一批 100 道题，A 对 64 道、B 对 68 道。若 B 独对 14 道、A 独对 10 道，二者都对 54 道、都错 22 道。净改善为 (14−10)/100=4 个百分点。边界接近、环境慢、运费高等题型的变化都能从这 24 道分歧题里找。只列两个均值会丢掉配对信息。

  1. 事先固定主指标、任务切分、采样温度、最大 token、工具预算、停止规则和选择 checkpoint 的 dev 集。测试集只用于方案定型后的比较。代码课中的参考结果是固定配置的演示，新消融先用 dev。
  2. 将同一任务两模型的结果成对重采样，对每次样本求平均差，再取分位数得到任务层面的 bootstrap 区间。若多个任务共享用户、文档或模板家族，应以相关性对应的簇重采样。用独立样本区间比较重叠与否会忽略配对结构。
  3. 同时更换训练种子，报告每种子的结果、均值和范围。对固定种子取任务 bootstrap 只描述该模型对新任务抽样的不确定性；三颗种子也不足以精确刻画训练波动。
  4. 对数据泄漏做结构检查。按家族、时间或实体划分；去除题面改写与镜像样本；隐藏测试判分条件；记录 benchmark 是否可能出现在模型预训练里。无法核实预训练语料时，只陈述能核实的划分与限制。

练习：一个值得留下的负结果

题面。 方案 A 单次 60%，平均 2 次工具调用；方案 B 单次 62%，平均 4 次。B 的 pass@4 为 91%，没有实际运行的选择器。团队只够运行 2,000 次工具调用，目标是尽可能多地完成相互独立的等价值任务。怎么汇报？

参考。 稳态且忽略其余开销时，A 大约尝试 1,000 题，期望完成 600 题；B 大约尝试 500 题，期望完成 310 题。若任务机会有限、每题价值不同或可重复尝试，结论会变。索要配对成功分布、开销分布、超时和选择器评估。可以报告 B 的单次成功率提高了 2 个百分点，并单独标明给定预算下的预期产出。仅凭这些数字还无法断言单次提升超出抽样波动。

第五课　从一条异常日志定位到一次实验

面试现场。 某轮训练的成功率下降，生成长度上升 28%，工具 P95 延迟上升 46%。你有 rollout、工具服务和 learner 三套日志。先说哪些指标缺了分母，再设计能把候选原因分开的实验。

沿一次请求走一圈

任务采样器选题与初始状态 → rollout 引擎生成助手 token → 解析器调用工具 → 工具结果进入历史 → 继续生成直至停止 → 验证器打分 → learner 重算 logp、求优势并更新 → 发布新策略版本。

同一任务使用贯穿全程的 trace ID，记录入队、首次 token、每次工具发出与返回、生成结束、判分和 learner 取样时间。分开看等待、prefill、decode、工具、验证器和优化耗时，按后端、任务长度、缓存命中、终止原因拆 P50、P95 和超时率。用户看到的耗时是链路墙钟时间，多个并发请求的服务时间不能直接相加。

算一个容量上界。 64 条轨迹由 8 个 worker 均匀处理。每条本地生成 0.4 秒、恰有一次 0.8 秒的工具调用，各 worker 处理自己的请求，不重叠生成与等待；工具完全并发且无排队时约需 (64/8)(0.4+0.8)=9.6 秒。若工具服务只能全局串行，光工具总服务时间就有 51.2 秒。要区分两种情况，就测并发中的在途请求数和服务端队列时间，单看 GPU 利用率无从推断。

三道训练系统白板题

显存用在哪？ 训练时区分参数、梯度、优化器状态、激活和临时张量。Adam 的矩估计随参数个数增长。长序列增大激活；生成时 KV cache 随在途序列和 token 数增长。若 rollout OOM 而 learner 正常，先看并发序列长度和 KV cache，再谈切 optimizer。梯度检查点通过重算减少激活显存；参数/优化器分片可省每卡常驻内存，却会增加通信。对 LoRA 微调，可训练参数和优化器状态下降，但冻结基座的前向计算与生成 KV cache 仍要付费。

怎样让吞吐口径有意义？ 一个批次每条平均有 400 个有效上下文与输出 token，其中 280 个是助手动作。有效动作占比为 70%。分别报告端到端任务/秒、生成 token/秒、有效训练动作/秒、每小时成功任务数。长工具回复会抬高重放时的 prefill，未必带来更多决策。压缩上下文前，用固定任务检查是否丢了选择所需证据。

何时改异步？ 同步方式易对齐 rollout 版本，却容易等最慢的工具。异步 worker 可把等待与其他任务交错，learner 则可能吃到落后多个版本的数据。日志要有 behavior version、消费版本、队列等待时间、有效动作 ratio 分布和丢弃率。若直接删最旧样本，延迟大的任务更容易被删，应审计难题和长轨迹是否系统性消失。

24 道 Agentic RL 深挖面试题

先只读粗体题干，给自己 90 秒作答，再读参考与追问。做第二遍时，把每个回答中的一个数字、一个数据条件或一个终止条件改掉，重新回答。下列情境均为教学设计。

时间紧先练 8 题。 第 1、11 题围绕同一条工具轨迹讲梯度与 mask；第 4、6 题用一正一负两个样本手算裁剪和组内优势；第 10、17 题要求拿出自己的失败记录及配对统计；第 18 题拿出重放温度实验的两个 logp；第 24 题只讲自己在这个小环境里真正验证过的结论。答完一题让同伴改一个条件，例如把工具返回换掉、把奖励全设为 1，随后重算。

一　策略梯度与目标函数

1．工具不可微，怎样训练决定调用它的模型？

写出轨迹概率，把 ∇p=p∇logp 代入期望，保留模型采样动作的 score。环境只给观测与奖励。追问“工具报价 token 有没有梯度”时，区分预测它的目标损失和通过其输入表示影响后续动作的梯度，在第三课的微型解码器上验证。

2．为什么减去 V(h) 不会改变期望梯度？把 baseline 设成动作成功率 Q(h,a) 呢？

给定历史，score 的期望为零，V(h) 可以提出期望。Q(h,a) 依赖采到的动作，通常不能提出。如果 G 的条件期望恰为 Q，直接用 G−Q 作权重，期望策略信号就会被抹掉。追问神经网络 baseline 时，补充 actor 更新应切断 baseline 的参数梯度。

3．GAE 的 λ=1 总能得到无偏优势吗？

完整终止时它望远镜求和成 Monte Carlo 回报减估计价值。回报可无偏估计 Qπ；当估计的 V 有偏时，数值优势与真实 Aπ 仍有差。与动作无关的 baseline 不必精确也能保持 on-policy score 梯度的期望。采集器在中途截断又会引入 bootstrap 误差。追问时画两道门并标出下一局的 reset 状态。

4．负优势 −2，ratio 从 1.1 到 1.5，PPO 是否停止惩罚？

ϵ=0.2 时目标分别为 −2.2、−3.0。坏动作概率越来越高，梯度仍在。若从 0.8 降到 0.6，裁剪目标停在 −1.6。追问“为什么还监测 KL”，答同一批抽到的单个 surrogate 平台无法约束所有状态和未抽动作。

5．在相同前缀，old 和 ref 都来自 SFT，它们一直相同吗？

第一次 rollout 时可能相同。采新一批前发布更新策略后，old 跟随生成版本，ref 可一直冻结。用 ref 做每一批的 ratio 分母，得到的比率没有对应这批行为概率。追问“单条参考 KL 为负”，给出样本 a 在当前概率低于参考概率的例子。

6．同题奖励为 [0,0,0,1]。把全 batch 一起归一化可以吗？

本组均值 0.25，总体标准差约 0.433，对应优势约 [−0.577,−0.577,−0.577,1.732]。把不同难度混一起会让全成功的易题也拿正优势，改变相对权重与目标。追问“组归一化无偏吗”，说明自包含均值产生有限组缩放，随机标准差又引入重加权。

7．提高组大小 G 能治稀疏奖励吗？

同题独立二元奖励时，可学习到组内差异的概率为 1−pG−(1−p)G。p=0 时无论 G 多大都没差异。追问“预算固定怎么试”，固定总轨迹数，分别记录非零组比例、覆盖的不同题数、真实成功率和调用开销。

8．两万对偏好、一千条成功演示、一个昂贵工具 API，你怎么起步？

先按目标任务建独立评估，用演示 SFT 学格式，偏好有信息时试 DPO；优先把在线预算花在有分歧或能验证的新前缀。若偏好几乎只按答案长度标，先做长度匹配和顺序翻转审计。追问“为什么不能直接比 DPO loss 和 RL reward”，说明量纲、数据分布与估计目标不同，应回共同评估。

9．拿通过验证器的轨迹再做 SFT，会有什么选择偏差？

易题和高频解法更易进入样本，失败前缀与恢复行为稀少。按题族记录被选入的比率，用同预算、相同题集的 rejection SFT 对比在线 RL。追问“生成更多一定好吗”，考虑验证器误接收率；搜索次数增大也会增加碰到假阳性的机会。

二　Agent 环境、长程任务与评估

10．模型查了两家却选错，应该改工具奖励还是策略？

先把原始返回、进入模型的历史、动作映射和独立判分串起来。若数据完整且选错，再定位是价格比较、位置偏好或输出解析。把两家顺序互换并控制价差，有机会区分这几个解释。追问“给每次查询加分”，指出可能奖励重复查询，设计高分失败反例。

11．为什么不能把整段多轮对话直接当成一句回答做 SFT？

用户和工具生成的 token 不属于策略动作。它们需作为后续条件输入，loss 只算模型应产生的目标。第一次错误常在角色边界错一位。追问“奖励在最后出现，工具返回能否完全删除”，举一个删去报价后得不到正确决策的反例。

12．任务超时用零价值 bootstrap 对吗？

若时间预算就是问题定义，超时是任务终止，可取零；若仅为采集切片且有真实后继观测，可用 V(hnext)，但优势递推不可跨新 episode。追问“后继观测丢了”，指出不能拿下一局初态顶替，修采集器并明确数据处置。

13．有一笔预算做步骤标注，怎么知道标哪个步骤？

先从失败分类找常见分歧前缀，例如“已见两家总价仍误选”。固定该处历史，多采样后续比较终局成功概率；优先标不确定且影响大的决策。追问“中间标签升了，终局没升”，检查奖励是否鼓励表面步骤以及评估器是否共用标注偏差。

14．如何验证 Agent 真的用了工具信息？

用隐藏报价互换构造配对反事实，保持题面和工具名相同，只改真实工具返回，看最后选择是否随赢家翻转。记录两次查询是否实际成功；打乱工具结果、屏蔽一次返回作负对照。追问“工具调用次数增加”，指出次数只说明动作频率，不能证明模型读取并利用了信息。

15．模型裁判和人类大体一致，可以直接优化吗？

在训练分布、策略更新后的分布上分别看假阳性/假阴性；检查顺序、长度、引用形式等偏好。固定人工留出集，盲审高 reward 低 gold 的分歧案例。追问“整体一致率 95%”，构造 95% 都是简单负例而难例全错的情况，要求按题型分层。

16．N 道题共跑 4N 次，怎样证明系统更可靠？

明确单次、至少一次命中、四次全对以及实际选择器性能。以同题结果聚合后在任务层统计，不把 4N 次同题尝试当作 4N 个独立任务。追问“无限重试能到 100% 吗”，考虑某题 p=0、工具服务共享故障与线上时延预算。

17．A 从 60% 到 64%，B 说没有统计意义，谁对？

先要每题配对结果和样本量；4 个百分点是点估计，不足以判定不确定性。按题或家族配对重采样，若随机训练再展示多个种子。追问“二者 95% 区间重叠”，单模型区间的重叠不能替代配对差的区间。

三　张量、系统与研究判断

18．同一 checkpoint 第一批 ratio 中位数为 1，P99 为 8，能开训吗？

检查尾部集中在哪些 token、worker、角色和模板。锁前缀逐步重算，同步温度、top-p、dropout、KV cache 和 old logp 来源；极罕见浮点差也应量化容差。追问“直接 clip 就好了”，说明裁剪会掩盖分布记录错误，影响优势和诊断。

19．两个 GPU 分别有 10、90 个有效 token，各自 loss 均值为 1、3，全局均值是多少？

(10+270)/100=2.8。直接平均两个均值得 2。追问 DDP 默认平均梯度，若目标是全局 token 均值，应以全局有效数为分母；在默认 world size 平均的实现中，要对局部分子相应乘 world size。注意框架是否已经做缩放。

20．只剩一晚，rollout 太慢，优先加 GPU 吗？

用事件时间线定位 prefill、decode、工具等待或验证器。缓存重放同一批工具响应看墙钟变化。工具串行时 GPU 扩容无法移除 51.2 秒的服务下界。追问“开异步”，记录版本滞后与被丢任务的长度分布，同时测成功任务/小时。

21．同题 8 个 rollout，worker 失败两次，能凑够 8 条重复写入吗？

以逻辑 sample ID 去重，重试保留尝试记录，按预定义的终止/重新采样规则处理。复制成功样本会改变组均值、方差和独立性。追问“只取回来最快的 6 条”，说明会偏向短、易完成任务，按难度审计被删比例。

22．训练总损失接近零，模型一定收敛了吗？

组居中的优势正负对消，ratio 初值为 1 时平均 surrogate 甚至可为零，同一参数上的梯度仍可非零。反之，全同奖组可能真的无奖励梯度。追问“你看什么”，答有效组比例、梯度范数、更新前后策略变化、独立成功率和输出分布。

23．从 1B 迁移到 7B 后训练 OOM，优先动什么？

先找是 rollout 还是 learner、长序列还是并发峰值。rollout 看 KV cache、批次与长度；learner 区分激活、参数、梯度和 Adam 状态，再选检查点或分片方案。追问“用 LoRA 就够吗”，解释基座前向、激活与生成 KV cache 仍然有成本。

24．面试官说规则程序已经 100%，你的项目为什么有意义？

诚实说明任务已知且小，生产上规则有优势。实验检验独立验证、奖励区分度、同种子对照与 OOD 误差，给出一条规则成功、学习策略失败的轨迹。追问“怎样证明对 LLM 有价值”，提出相同工具环境下的文本策略对照、采样预算和停止条件，并把已经测过的结果与待验证假设分别表述。

一个完整的阅读示范

以 DAPO 的动态采样为例。若训练组全对或全错，组内回报标准化后奖励优势为零。过滤这样的组，再补采有信号的组，可增加每个优化 batch 内有奖励梯度的样本。代价是额外 rollout，而且被留下的题更可能处于当前策略的中等难度区间。这是一个能改变研究结论的机制。

  1. 提出假设。 给定相同优化步数，动态补采能提高每步有效组比例；给定相同工具调用总数，最终收益可能变小。两个假设应分别检验。
  2. 做最小对照。 A 使用固定组数；B 对零方差组补采，记录所有被丢弃轨迹。先用同一真核验奖励、SFT 初值、G、学习率和任务池。不通过调大 B 的生成预算来冒充算法增益。
  3. 定义横轴。 同时画成功率对 optimizer step、生成轨迹数、实际工具调用数的关系。极难题若一直没有有效组，应有尝试上限并记录最终舍弃的题族。
  4. 预判会推翻什么。 若 B 按步数更快，按工具调用数反而落后，论文机制仍能解释更密的更新信号，业务端的优越性则缺少支持。若两者均改善，还要检查题目分布是否改变以及未被过滤的最终评估是否覆盖难题。
