# 第五课　从一条异常日志定位到一次实验

**面试现场。** 某轮训练的成功率下降，生成长度上升 28%，工具 P95 延迟上升 46%。你有 rollout、工具服务和 learner 三套日志。先说哪些指标缺了分母，再设计能把候选原因分开的实验。

## 沿一次请求走一圈

任务采样器选题与初始状态 → rollout 引擎生成助手 token → 解析器调用工具 → 工具结果进入历史 → 继续生成直至停止 → 验证器打分 → learner 重算 logp、求优势并更新 → 发布新策略版本。

同一任务使用贯穿全程的 trace ID，记录入队、首次 token、每次工具发出与返回、生成结束、判分和 learner 取样时间。分开看等待、prefill、decode、工具、验证器和优化耗时，按后端、任务长度、缓存命中、终止原因拆 P50、P95 和超时率。用户看到的耗时是链路墙钟时间，多个并发请求的服务时间不能直接相加。

**算一个容量上界。** 64 条轨迹由 8 个 worker 均匀处理。每条本地生成 0.4 秒、恰有一次 0.8 秒的工具调用，各 worker 处理自己的请求，不重叠生成与等待；工具完全并发且无排队时约需 $(64/8)(0.4+0.8)=9.6$ 秒。若工具服务只能全局串行，光工具总服务时间就有 51.2 秒。要区分两种情况，就测并发中的在途请求数和服务端队列时间，单看 GPU 利用率无从推断。

## 三道训练系统白板题

**显存用在哪？** 训练时区分参数、梯度、优化器状态、激活和临时张量。Adam 的矩估计随参数个数增长。长序列增大激活；生成时 KV cache 随在途序列和 token 数增长。若 rollout OOM 而 learner 正常，先看并发序列长度和 KV cache，再谈切 optimizer。梯度检查点通过重算减少激活显存；参数/优化器分片可省每卡常驻内存，却会增加通信。对 LoRA 微调，可训练参数和优化器状态下降，但冻结基座的前向计算与生成 KV cache 仍要付费。

**怎样让吞吐口径有意义？** 一个批次每条平均有 400 个有效上下文与输出 token，其中 280 个是助手动作。有效动作占比为 70%。分别报告端到端任务/秒、生成 token/秒、有效训练动作/秒、每小时成功任务数。长工具回复会抬高重放时的 prefill，未必带来更多决策。压缩上下文前，用固定任务检查是否丢了选择所需证据。

**何时改异步？** 同步方式易对齐 rollout 版本，却容易等最慢的工具。异步 worker 可把等待与其他任务交错，learner 则可能吃到落后多个版本的数据。日志要有 behavior version、消费版本、队列等待时间、有效动作 ratio 分布和丢弃率。若直接删最旧样本，延迟大的任务更容易被删，应审计难题和长轨迹是否系统性消失。

## 故障会诊

| 观察 | 至少两种解释 | 优先做的区分实验 | 据结果怎样处理 |
|---|---|---|---|
| 更新前 ratio P95=1.8 | 温度/模板错位；worker 用旧 checkpoint | 锁一个 token 前缀，对齐模型哈希、原始 logits、采样变换后的 logp | logits 一致则查温度和截断，不一致则查版本、token、位置与数值精度 |
| 训练 reward 涨，独立成功率跌 | 奖励被重复调用利用；任务分布改变 | 用两版判分器重放同一批高分与低分轨迹，按题族分层 | 固定题也分歧则修指标；只在新题族下降则查采样权重 |
| 所有组优势几乎为零 | 全失败；全成功；判分器卡在常数 | 分开数全一/全零组，给验证器喂已知正反例 | 先校准判分器，再调难度、示范或多样性 |
| GPU 空闲，P95 上升 | 工具限流；长尾生成；队列被慢任务卡住 | 录制相同请求，换等长缓存结果重放，分阶段计时 | 工具等待消失就看并发/限流；仍慢就看 decode 长度和调度 |
| loss 突变且偶发 NaN | 全 mask 分母为零；半精度 exp 溢出；常奖励除零 | 找第一处非有限张量，存该 batch 的 mask 和 logratio 极值 | 修具体源头；静默丢 NaN 会掩盖题族偏差 |
| pass@8 涨但单次跌 | 解码更随机；少数题反复重试；选择器弱 | 固定预算画每题单次、多次、真实选择器三条曲线 | 报告重试成本与线上能实现的成功率 |

**逐层追一个具体故障。** 假设只有工具返回后的第一个动作出现 logp 偏差。先取偏差最大的同一 trace，把工具前后完整 token ID 对齐。若工具后多一个换行，固定模板渲染，重采同一批，再看 ratio 是否回到 1 附近。若 token 完全相同，再比较 attention mask、position ID 与 KV cache 重用边界。全局调低学习率无法修复首个优化步之前已经存在的差异。

**本地必做。** 先完成第三课的温度故障实验，拿相同 token 前缀上的 old/new logp 回答「偏差发生在 optimizer step 之前还是之后」。本节其余的异步队列、工具 P95 和 GPU 显存题属于系统设计训练。遇到吞吐方向的 JD 时，优先选一道做容量估算，再说明实际部署需要采集哪些数据。[重放实验](03-多轮训练与张量.md)

## 设计可恢复的采样器

面试官要求同题并发采 8 条轨迹，外部工具会超时，worker 可能重启。把逻辑样本标成 `(task, group, sample, policy_version)`，把一次逻辑调用的重试尝试单独编号。带副作用的工具若支持幂等键，同一逻辑调用重试应复用它。没有确定执行状态时先查询/对账，防止一次下单变成两次。成功落库要去重，每个组明确收齐、超时或丢弃的策略。记录丢弃比例与任务难度。组归一化不能把丢失的样本伪造为真实失败；将超时计作任务失败是否合理，取决于预先定义的环境语义。

**框架阅读作业。** 在 verl 文档找到 rollout、actor update、reward 的入口，画出数据从生成端到 learner 的方向。把你用的版本号和仓库路径写进笔记，圈出行为 logp 保存处和 loss 聚合处。换框架时仍然能用这两个边界调试。[verl 文档](https://verl.readthedocs.io/en/latest/)
