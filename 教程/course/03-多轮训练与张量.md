# 第三课　把多轮对话变成可以反传的 batch

**现场题**　训练日志里的 loss 在降，但模型越来越爱复述工具输出。你打开一条序列，看见下面这些 token。先用手指出，哪一行 logits 正在被优化。

```text
索引                 0      1       2       3       4       5
输入 token        USER     查A    A报价     选A     EOS     PAD
归属              用户    助手     工具    助手    助手    填充
目标动作 mask        0      1       0       1       1       0
预测它的 logits      —      0       1       2       3       4
```

自回归模型在位置 $j$ 的输出预测位置 $j+1$ 的 token。给 logits 删最后一列时间步，给目标 token 和动作 mask 删第一列。此例取 logits 行 0、2、3。工具报价对应的 **输入表示** 参与了后续选 A 的判断；预测报价 token 的那一行 **输出损失** 应被屏蔽。两者可以同时成立。[可运行的梯度检查](../lab/drills.py)

## 数据从哪里来

1. **采集。** 固定行为策略版本，采样一段助手输出，工具执行器解析参数、验证 schema、生成观测。把原始 token ID、每步选中 token 的行为 logp、发出者、task/group ID、环境与策略版本、停止原因存下来。判分使用的隐藏答案留在验证器端。
2. **拼接。** 下一段助手文本能够看到符合因果顺序的历史。工具回复、用户消息、pad、模板注入的角色标记，默认不算模型采样动作。模型自己产生的终止 token 可计入；运行器强制插入的分隔符应标为外生。若推理模板和训练模板对空格或换行处理不同，重新分词可能改变整段 token ID。
3. **重放。** 训练侧对固定序列做 teacher forcing，从全词表 log-softmax 中 gather 当时抽到的 token。大模型用 KV cache 逐 token 生成，训练时并行打分；相同模型、分布和历史下，二者在数值容差内应得到相同的选中 token logp。
4. **更新。** 保持优势、旧概率、参考策略冻结。当前策略通过有效动作的损失更新。按 episode 切开 bootstrap，按原始 task 分组算优势；若按长度重排 batch，需要携带 group ID 再还原组关系。

## 四个张量题

在项目根目录运行以下命令。这会生成你自己的答题文件。每过一关，解释一个能让错误实现暴露出来的输入。答案在[参考实现](../lab/solutions.py)，判卷器在[自测脚本](../lab/drills.py)。

```powershell
Copy-Item lab/starter.py lab/mine.py
python lab/drills.py mine
```

| 函数 | 输入与输出 | 自测抓什么 |
|---|---|---|
| `action_logps` | logits `[B,L,V]`、ID 和两个布尔 mask `[B,L]` → 两个 `[B,L-1]` 张量 | 行偏移、左右填充、外部观测零目标梯度；微型 GRU 逐前缀重算应一致 |
| `gae` | reward、value、next_value、bootstrap、carry 各 `[B,T]` → 优势 `[B,T]` | 真终止与采集截断不同，不能跨 reset 传播 |
| `group_adv` | 同题一行 `[B,G]` → 等形状 | 全成功、全失败不出 NaN；总体标准差与样本标准差不同 |
| `clip_loss` | 当前 / 旧 logp、优势、有效位各 `[B,T]` → 标量 | 正负优势、裁剪平台、旧概率无梯度；空动作 batch 显式报错 |

四项通过后，运行 `python lab/token_rollout.py --implementation mine`。训练循环会用你写的 `group_adv` 和 `clip_loss` 做 Transformer 的一次更新，终端会列出 `implementation=mine`、有效动作数、梯度范数和更新次数。把自己的实现接进训练，还能查出只在真实 batch 上出现的形状问题。另两项练习分别检查 token 对齐和 GAE 边界。

**复盘代码的顺序。** 先写只含一个有效动作的样本，再混进 pad 和一个工具 token，最后让同一组奖励完全相同。把一个已知错误引入自己的答案，例如把 `assistant[:, 1:]` 改成 `assistant[:, :-1]`，观察哪个断言首先失败，然后修回去。现场说出失败原因比背出切片语句更能说明你掌握了对齐。

## 面试官的三个变体

先检查一个前置概念。自注意力的权重来自 $\mathrm{softmax}(QK^\top/\sqrt{d_k}+M)$，因果 mask 让当前位置看不到未来，padding mask 让它忽略填充；乘上 $V$ 才得到上下文表示。前面的助手动作 mask 则决定哪些预测进入标量损失。这三个 mask 回答不同问题。增量生成复用旧 token 的 K、V，省去重复计算历史表示；训练侧一次处理整段序列仍需正确的因果约束。

**一、变长轨迹如何加权？** 轨迹一有 1 个动作，单项损失为 1；轨迹二有 3 个动作，单项损失均为 3。所有动作取平均得 $(1+9)/4=2.5$。每条轨迹先平均再按轨迹平均得 $(1+3)/2=2$。每条求和再按轨迹平均得 $(1+9)/2=5$。最后一种对应朴素的整轨迹 log 概率求和。实际训练中的长度归一化、全局 token 归一化和终止奖励都能影响长度偏好。项目采用第三种，张量练习采用第一种，换实验要记录分母。分布式训练各 rank 的有效动作数可能不同，先求局部均值再平均会给短 batch 过高权重。

**二、packing 怎样静悄悄地泄漏？** 直接把两个不同任务首尾相接，即便第一个位置的 loss 被遮住，第二条轨迹仍可能通过注意力读到上一条。按样本边界做分块因果注意力，并检查位置 ID、目标偏移、组 ID、GAE 递推均没有跨段。给第一条序列换成随机 token，第二条在相同位置设定下的 logits 应在容差内保持一致。

**三、相同 checkpoint 为什么 ratio 不是 1？** 优先检查模型版本、输入 token 与位置、dropout、温度和 top-p。设模型原分布 $(0.8,0.2)$，温度 $T=2$ 后分布约为 $(2/3,1/3)$。若抽到第二项，用原分布当前概率除采样概率就得到约 0.6，同一参数也会偏离 1。必须定义实际优化与记录的是哪种分布。top-p 会截断支持集，记录截断后的 logp 可以解释行为样本，无法凭此恢复从未被采到的动作。在多轮工具学习中，对齐采样和优化的分布是最容易验证的起点。

## 从小网络迁移到语言模型

**先亲手走一次 token 级闭环。** 在根目录运行 `python lab/token_rollout.py`。这是一个随机初始化、单层的因果 Transformer。它先在允许的操作 token 中抽 `GET/SUBMIT`，再在参数 token 中抽 `A/B`；环境追加 `TOOL HIGH/LOW`，模型据此继续。每组 16 条轨迹在相同隐藏报价上采样，用终局核验计算优势。脚本拼回整段历史，一次前向重算所有动作概率，断言与采样侧一致，再执行一次真实梯度更新。[token 级 rollout 实现](../lab/token_rollout.py)

**做一次可复现的排错练习。** 固定种子、权重、前缀、动作和采样端温度 1，只修改 learner 的重放温度。先预测低概率动作的 ratio 会往哪个方向变，再执行。第一条命令会显示诊断并以错误退出，第二条应完成一次更新。

```powershell
python lab/token_rollout.py --replay-temperature 2
python lab/token_rollout.py --replay-temperature 1
```

本机故障输出中，前缀是 `USER COMPARE BOT GET A TOOL HIGH BOT GET`，选中 `B`。采样 logp 为 −1.84855，重放为 −1.19789，所以 ratio 约为 `exp(0.65066) = 1.917`。两端已经用了同一个前缀，且此时优化步数为零。恢复温度 1 后，412 个有效动作 token 的最大 logp 绝对误差从 0.65065 回到 2.38e−7。把你自己的两份输出放在一起，解释哪个假设被排除了。这个案例属于主动注入的故障，复述时说明实验条件。

本机固定种子实测，128 条轨迹里有 1 条核验成功，412 个有效动作 token，更新前选中动作 logp 的最大绝对差是 $2.38\times10^{-7}$。其中一条成功轨迹为 `GET A → HIGH → GET B → LOW → SUBMIT B`。读代码时注意两个位置：提交后的占位步怎么屏蔽，以及采样与重放如何使用相同的二选一语法约束。只把重放端改成全词表 softmax，看看一致性断言如何捕获错误。一次更新用于验证接口与梯度；模型在大规模训练后的成功率需要另一项实验来测。

| 小实验里看得见的量 | 换到语言模型时的具体对象 |
|---|---|
| 四分类动作 | 查价工具名称与 JSON 参数会拆成多个 token；整次调用 logp 是其各生成 token 条件 logp 之和 |
| 七维状态输入 | chat template 渲染的系统提示、用户请求、历史工具结果，加上上下文长度和工具预算约束 |
| 一次查价后追加报价 | 在推理引擎暂停生成、运行工具、把输出作为外生消息追加，再续写 |
| 冻结 old logp 的两次优化 | rollout 服务写出带版本的序列，learner 对每个有效 token 重新打分 |
| 枚举四动作求精确 KL | 全词表 KL 或选中 token 的估计；记录采样分布、方向与 mask |

如果一个工具调用内部有 15 个 token，把 15 个 token 的 ratio 相乘可得到这个完整动作的概率比，方差和裁剪行为都会改变。逐 token 裁剪后再求和一般不会等于先求乘积再裁剪。面试中明确实现粒度，才能和论文公式对上。
