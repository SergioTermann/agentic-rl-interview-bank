# Agentic RL 秋招面试课

这套课给会读 PyTorch 训练代码、准备投 Agentic RL 算法或研究工程岗的同学。主项目只有一条规则：三步内查完两家报价，选中到手价较低的供应商才算成功。你会跟着同一条轨迹，从工具观测算到参数更新，再用失败样本检验自己的解释。

## 先学哪几件事

| 优先级 | 要回答的问题 | 做完后手里有什么 |
|---|---|---|
| **P0 · 轨迹与信用分配** | 工具结果进入上下文以后，谁的动作有 logp？终奖怎么影响前面的查询？ | 一条标了角色、动作、预算和终止原因的轨迹；一个 baseline 和优势的手算例子。[第一课](course/01-轨迹与策略梯度.md) |
| **P0 · 如何更新策略** | 手上是示范、偏好对，还是可反复采样的环境？选择 SFT、DPO、PPO、GRPO 的依据是什么？old 和 ref 从哪来？ | 手写 GAE、正负优势下的裁剪、同题组内归一化；能指出实际项目用了哪些更新。[第二课](course/02-后训练算法.md) |
| **P0 · 概率与梯度** | 同一权重、同一前缀，采样和重放算出的动作概率应怎样对齐？ | 自己实现的四个张量函数，一次故障注入与修复前后的 logp，一次真实的 optimizer step。[第三课](course/03-多轮训练与张量.md) |
| **P0 · 奖励与评估** | reward 满分，任务为何还会失败？有多少题改善，花了多少工具调用？ | 一条高代理奖励却失败的轨迹，分母明确的配对比较，以及一次自己选变量做的消融。[第四课](course/04-奖励探索与评估.md) · [项目手册](course/06-项目实验手册.md) |
| **P1 · 岗位工程** | 当 JD 写了 rollout、训练系统或吞吐优化，怎样定位版本滞后、工具等待和 OOM？ | 按阶段画数据流，给一个异常设计区分实验。已有 CPU 实验能验证训推概率；GPU 显存和分布式性能留给有对应环境时实测。[第五课](course/05-训练系统与诊断.md) |
| **P2 · 研究延伸** | 为什么要筛掉零方差组？过滤以后，固定优化步数和固定采样预算得出的结论一样吗？ | 选与自己失败样本有关的一篇论文，提出一个能在现有预算下验证的假设。[论文与研究设计](course/09-论文与研究设计.md) |

这几项优先级取自与你目标最接近的三篇面经。字节追问轨迹字段和如何排除随机波动；百度文心追问三种策略的概率来源；华为从 GRPO 伪代码问到 loss 怎样更新参数。其他团队按各自 JD 调整。[公开面经与原帖](course/10-公开面经索引.md)

## 今晚的第一小时

1. **先算，10 分钟。** A 的商品价 9、运费 14，B 的商品价 13、运费 8。模型先查 A、再查 B、最后交 A。写下这条轨迹的提交奖励、真实核验奖励，以及错误发生在哪一步。
2. **查代码，15 分钟。** 在 `train.py` 的 `rollout` 中找到 `submitted`、`correct`、`verified`。把“直接提交 B”也算一遍，解释它和“查全再交 B”在三个字段上有什么差别。[环境与判分](lab/train.py)
3. **自己跑，20 分钟。** 在本目录打开 PowerShell，执行下面两条命令。第一条跑参考实现，确认环境可用；第二条生成你自己的逐题记录。在 `cases.csv` 找到种子 3、`sft-grpo`、`shift` 的任务 21，对照你刚才的手算。安装说明在[项目手册](course/06-项目实验手册.md)。
4. **试着推翻解释，15 分钟。** “它选了商品价便宜的一家”与“它总爱选 A”都能解释这一次错误。设计一对输入，使这两种解释预测不同的结果。把预测写在运行下一项实验之前。

```powershell
python lab/drills.py
python lab/train.py --methods sft sft-grpo sft-proxy --seeds 3 --cases --output runs/first
```

取出这道题的原始记录，对照报价和动作。若把最后一个动作换掉，哪些指标会随之改变？

```powershell
Import-Csv runs/first/cases.csv |
    Where-Object method -eq 'sft-grpo' |
    Where-Object split -eq 'shift' |
    Where-Object task_id -eq '21'
```

## 八周怎么用

按每周 8–10 小时安排。每周留下一个别人接手后也能重查的结果。

| 周 | 做什么 | 留下什么 |
|---|---|---|
| 1 | 拆查价轨迹，手推 REINFORCE | 一张标出外部反馈、动作损失和奖励回传范围的图 |
| 2 | 手算 GAE、PPO 裁剪、GRPO 优势；比较偏好学习的数据条件 | 一页手算，其中包含负优势和全组同奖两个边界 |
| 3 | 从 `starter.py` 写四个函数，运行 `python lab/drills.py mine`，再用 `python lab/token_rollout.py --implementation mine` 更新一次 | `mine.py`、断言结果、一条有效动作的 logp |
| 4 | 核对代理奖励与真实核验；算配对差和按任务计算的 pass@k | 一份含任务分母的对照，以及一个被代理奖励接受的失败样本 |
| 5 | 在固定前缀上改变重放温度，定位更新前 ratio 异常 | 修复前后的同一前缀、被选动作、最大 logp 误差 |
| 6 | 跑六种方法、三个种子；按商品价排序和到手价排序切分失败 | 一份结果表，至少一个不符合预期的种子或切片 |
| 7 | 提前写下预测，独立改一项设置，记录轨迹数和工具调用数 | 一页个人实验记录，写清自己改了什么和哪条证据改变了判断 |
| 8 | 先做优先题，再请同学任选一条轨迹或一行代码继续追问 | 一次闭卷推导、一次现场编程、一轮项目答辩。[深挖题](course/07-深挖面试题.md) · [计时模拟](course/08-模拟面与答辩.md) |

**两周内要面试**，前 4 天做轨迹、手算和张量自测，第 5–8 天做重放排错与三种子实验，第 9–11 天完成一次个人消融，第 12–14 天做三轮模拟并重做最弱的一轮。P1 按岗位补，P2 留到有人追问你的研究假设时再展开。

## 到什么程度可以讲这个项目

让同学随机点开你的一条失败记录。你能从输入重算结果，解释哪个动作收到了梯度，指出一处自己改过的实现，再说清“如果改动无效，我会在哪个指标看到它”。复现课程参考代码、自己实现过的部分、仅提出的设想，分别用这三个准确的动词表达。面试用的数字从自己的运行目录取。[项目记录写法](course/06-项目实验手册.md) · [项目答辩评分](course/08-模拟面与答辩.md)
