算法原理 · 12 分钟

Q01　哪一组 rollout 真能给策略梯度？

同一任务独立采样四条轨迹，终局奖励是 [0, 0, 0, 1]。定义优势为组内减均值再除以总体标准差，零方差组的优势置零。手算四个优势，说明它们怎样分配给每条轨迹中的助手动作。另一道题四条全对，第三道题四条全错。三道题放在一起归一化，训练信号会怎样变？你会用什么统计量决定是调难度、改验证器还是继续采样？

判分与追问 · 每项 1 分
  1. 均值 1/4，总体标准差 √3/4，前三条优势各 −1/√3，赢家 +√3。
  2. 在终奖版 GRPO 中，同一轨迹的有效助手动作共用轨迹优势；工具返回参与后续条件输入。
  3. 全对和全错组的相对奖励梯度均为零，跨题归一化会让简单题和困难题互相充当基线，改变权重。
  4. 分开报全对、全错、混合组的数量和分母，先用已知正反例核查 verifier，再按题型看采样多样性。

加压追问。 给定某题独立成功概率 p，G 次采样有信号的概率是多少？期望答出 1−pᴳ−(1−p)ᴳ，并指出共享工具故障会破坏独立性。若候选人认为零优势保证参数不动，问还有哪些损失或优化器状态在更新。

算法原理 · 12 分钟

Q02　一个负优势样本究竟有没有梯度？

用 PPO 的裁剪目标最大化期望回报，ε=0.2。对优势 +2 和 −2，分别算出 ratio 为 0.6、1.5 时的单项 surrogate，共四个数。任选一项，判断对当前策略 logp 的梯度方向。说明生成样本的策略、当前策略和冻结的参考策略在代码里各提供什么。训练日志显示很多 ratio 越界，你还需要知道什么，才能判断有多少项落在梯度平台上？

判分与追问 · 每项 1 分
  1. 对正优势，ratio 0.6、1.5 的目标依次为 1.2、2.4。
  2. 对负优势依次为 −1.6、−3.0；后者仍惩罚增加坏动作概率。
  3. 最大化 min(rA, clip(r)A)；以 A=−2、r=1.5 为例，对当前 logp 的导数为 −3，最小化负目标时取反。
  4. 行为策略提供冻结分母，当前策略提供可导分子，参考策略用于约束；要区分越界率和落入平台的比例，需联合看优势符号和越界方向。

加压追问。 若整批 old 用更新后的模型重新计算，记录的 ratio 有何假象？相同打分会得到 1，掩盖相对实际行为策略的漂移。能说明下一步该检查哪个 checkpoint 和哪条旧 logp，即可接受不同术语。

算法原理 · 12 分钟

Q03　先做 DPO，还是花钱收在线轨迹？

你有 2,000 对同题偏好数据、少量工具调用示范和 3,000 次工具调用预算。目标是提高用户任务的一次完成率。对一对偏好，当前模型相对参考模型的序列 logp 差分别为赢家 +0.3、输家 −0.2，β=2。写出 DPO 损失并算出本项近似值。设计一个起步方案，再说明什么观察会让你把下一笔预算从离线学习移到在线 RL。

判分与追问 · 每项 1 分
  1. 写出 −log σ(β(Δw−Δl))，本例为 −log σ(1)≈0.3133。
  2. 说明序列 logp 用响应中有效模型动作的条件 logp 求和，固定参考与配对条件；检查偏好标签质量。
  3. 设计可行起点，如示范 SFT 建格式、固定偏好对做 DPO，在同任务与同解码预算下分别评估。
  4. 指出离线数据覆盖不到的失败前缀，给出重置环境、独立 verifier 和在线预算分配的实验。

加压追问。 如果偏好赢家几乎总是更长，先切哪组数据？接受同长度区间配对、长度受控的人工复核或反事实改写，需说明内容保持一致的办法。若预算改为零，能保留哪些离线检查？

算法原理 · 12 分钟

Q04　第三步选错，该给前两次查询扣分吗？

查价任务要求在三个动作内查齐 A、B 两家的报价并提交便宜的一家。A 的商品价 9、运费 14；B 的商品价 13、运费 8。轨迹是「查 A → 查 B → 交 A」。写出策略在每一步实际能看见什么，标出环境产生的观测和策略产生的动作。解释一个终局分数怎样影响各步的学习，再设计一对能区分“偏爱第一个选项”和“过度依赖商品价”的输入。

判分与追问 · 每项 1 分
  1. 初始无报价，第一次查询后只见 A，第二次后才见 A 和 B；总价 23 与 21，提交 A 得零。
  2. 轨迹似然中策略对三次动作打分，环境负责返回报价；离散动作靠 score function 与回报关联。
  3. 区分估计器：原始零回报 REINFORCE 此条奖励项为零；若基线为正则可得负优势。共享终奖不能靠单条样本准确定位哪步致错。
  4. 固定两次有效查询并交换两家的整份报价，使新 A 商品价 13、总价 21，新 B 商品价 9、总价 23。固定偏爱 A 与固定追求低商品价给出不同预测，评估时需控制输入顺序和解码随机性。

加压追问。 重复查 A 再碰巧交对 B， verifier 应读哪条记录？读工具执行成功事件及最终选项。若按“每次查询加分”，重复查询可能在耗尽预算前累积分数。

现场编程 · 25 分钟

Q05　现场编程：多轮对话的 SFT loss

实现 sft_loss(logits, ids, assistant, valid)。输入为 [B,L,V] 的未归一化 logits、[B,L] 的合法 token ID，以及两个同形布尔张量。每行一条连续的因果序列，可左填充或右填充。assistant 标注由模型实际生成的目标 token，包括模型采到的 EOS。返回所有可预测且有效的助手目标的平均交叉熵；若整批没有目标，抛出 ValueError。允许工具 token 作为输入。

举例说明：一行是「PAD、用户、助手查价、工具报价、助手提交、EOS」。请标出用于打分的 logits 行，再写一个能抓到偏移一位错误的测试。只用常数 logits 的测试够吗？

判分与追问 · 每项 1 分
  1. logits 去掉最后一个时间步，目标取 ids[:,1:]。
  2. 动作掩码取目标侧的 assistant 与 valid，预测位置也须 valid；题中有效 logits 行按零起始是 1、3、4。
  3. 在词表上算交叉熵或 log-softmax 后 gather，仅对有效项取均值，空 batch 抛指定异常。
  4. 用非均匀 logits 构造方向敏感的例子，并用左填充、右填充、工具位或梯度断言发现错误。常数 logits 可检验部分 mask 行为，却难发现选错词或时间步。

加压追问。 工具报价位为什么可能收到梯度？区分「预测报价的输出行」与「报价作为输入时的 embedding」。接受两种等价实现。典型扣分是把 logits[:,1:] 用来预测同位置目标。可运行参考与边界样例

Q06　现场编程：乱序组上的 GRPO 更新

实现 grpo_loss(new, old, reward, group_id, mask)。new/old 是相同动作的 logp，形状 [N,T]；每条轨迹一个终奖和一个组 ID，形状 [N]。每行至少有一个有效动作，但同题的行可能交错。按题用总体标准差和 1e−6 做标准化，全同奖组优势取零。采用 ε=0.2 的裁剪目标，本题要求按全批有效动作数取平均，返回待最小化的标量。仅 new 接受梯度。

自己构造一个四行 batch，包含一个全同奖组和一个有输赢的组。再选一个负优势样本，把 ratio 调到 1.5，看梯度是否符合你的预测。

判分与追问 · 每项 1 分
  1. 按 group ID 聚合，不依赖连续布局，奖励数值冻结；总体标准差和零方差处理正确。
  2. 冻结 old，对有效动作求 exp(new−old)，将轨迹优势广播到时间维。
  3. 取两支 surrogate 的最小值再取负，除以全批有效动作数。
  4. 自造全同奖组和负优势样例，验证平台方向、无效位梯度为零、old/reward 无梯度。

加压追问。 顺序为组 7、9、7、9，奖励依次为 0、1、1、1。忽略微小量，优势依次为 −1、0、+1、0。第一条 ratio 改为 1.5 时，对该 new logp 的负目标梯度约为 +1.5 除以有效动作数。若候选人直接 reshape 成两行，用该样例重测。可运行参考与边界样例

现场编程 · 25 分钟

Q07　现场编程：截断处的 GAE

实现 gae(r, v, next_v, bootstrap, carry, valid, gamma, lam)。前六个参数均为 [B,T]，后三个矩阵为布尔门。bootstrap 表示允许使用真实后继的价值，carry 表示允许连接到同一片段的下一项优势。无效位输出零，目标不参与反传。本题输入均为有限数；拼接两局时边界已标出。解释为什么要有两道门。

在同一行试算 r=[0,1,3]、v=[.2,.5,.7]、next_v=[.5,.8,100]，三项都有效。第一步正常，第二步是采集截断且真实后继已知，第三步属于新 episode 并真正终止。取 γ=1、λ=0.5，写出预期结果再运行。

判分与追问 · 每项 1 分
  1. TD 残差为 r+γ·bootstrap·next_v−v。
  2. 倒序递推时乘 γλ·carry，截断可用末状态价值但不递推至新局。
  3. 无效位返回零且不向前连接，不让 actor 通过优势回传，输入终局后继 100 也能正确屏蔽。
  4. 本例残差 [0.3,1.3,2.3]，优势 [0.95,1.3,2.3]，用包含 padding 或不同 λ 的额外样例验证。

加压追问。 如果环境自动 reset 后只给了下一局的初始观测怎么办？应从采集器保存真实末状态或明确处置缺失的 bootstrap；任务预算本身耗尽可定义为真终止。可运行参考与边界样例

现场编程 · 25 分钟

Q08　现场编程：带重试的分组收集器

实现生成器 complete_groups(events, G)。有限事件流的每项为 (task, version, sample_id, reward)，ID 为 0 至 G−1，重复投递的内容相同。每凑齐一组，就按完成顺序产出 (task, version, rewards)，其中 rewards 按 sample_id 排序。同一组只能产出一次，流末尾留有缺失 ID 的组不产出。允许使用内存字典，先按单进程设计。

G=2，输入依次为 (q,1,1,7) (z,1,0,8) (q,1,1,7) (q,2,0,9) (q,1,0,5) (z,1,1,6) (q,1,0,5) (q,1,1,7)。写出输出，并解释如果这项服务运行一整年，你会如何处理内存和重试窗口。

判分与追问 · 每项 1 分
  1. 键同时含 task、version，不会跨版本拼样本。
  2. 按 sample_id 去重，收齐才 emit，并按 ID 排序。
  3. 先输出 (q,1,[5,7])，后输出 (z,1,[8,6])；末尾的 (q,2) 不完整；已完成组的完整重投不会再次发出。
  4. 说明 pending、completed 的空间代价，以及过期策略、有限重放窗口或有状态持久去重可保证到什么范围。

加压追问。 发送成功但写完成标记之前进程死了，单机 set 是否够用？接受事务性 outbox 或下游按幂等键去重，须解释写入顺序与重复消费。正常处理事件哈希操作均摊常数，输出一个完整组还要 O(G)。可运行参考与边界样例

训练排错 · 15 分钟

Q09　还没更新，动作的概率比为什么偏离 1？

同一工具调用前缀，rollout 在合法参数 A、B 中采到 B。记录的 old logp 是 −1.84855；learner 在首次 optimizer step 前重算为 −1.19789。权重哈希相同，dropout 已关闭。算出概率比，给出两种能产生这种现象的机制。你只能先取一条轨迹，具体会取哪几个字段、做什么比较，再决定是否开训？

判分与追问 · 每项 1 分
  1. 算出 exp(−1.19789+1.84855)≈1.917，指出这是选中 B 的比值。
  2. 提出两种机制，例如同串文本经不同模板分词、位置或掩码不同、温度不同、合法词集合不同。
  3. 锁同一前缀的 token ID、动作 ID、位置、版本，比较变换前 logits，再比较温度及约束后的选中动作 logp。

Q12　双卡训练为何总是偏向短序列？

某实现对每张卡本地的有效助手 token 求平均 loss，DDP 再对梯度取两卡均值。A 卡有 10 个有效 token，本地均值为 1；B 卡有 90 个，本地均值为 3。目标是让全局每个有效 token 权重相同。算出当前报表值和目标值，推导每个 rank 应反传哪个标量。再处理一张卡全是 padding 的 batch，说明各个 rank 应如何走 collective 和 backward。

判分与追问 · 每项 1 分

  2. 设本地有效 loss 之和为 Sᵣ，全局有效数为 N，DDP 平均梯度时各 rank 应反传 W·Sᵣ/N。
  3. 全局 all-reduce 有效数；空 rank 也参加 collective 和 backward，提供与参数相连的零。
  4. 全局 N=0 时各 rank 统一跳过该次优化并记录，避免除零或一部分 rank 卡住。

加压追问。 只修报表汇总能修梯度吗？让候选人构造两个 rank 梯度方向相反的情形。只在显示端加权不会改反传权重；若用梯度累积，还要说清 N 覆盖的累积窗口。

Q14　pass@4 能不能写进单次服务的指标？
